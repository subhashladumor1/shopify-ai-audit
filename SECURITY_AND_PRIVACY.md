# SECURITY AND PRIVACY SPECIFICATION

**Package:** `subhash/shopify-ai-audit`  

---

## 1. Package Self-Protection & Invariants

Because Guardian scans source code, executes shell analyzers, and processes webhook payloads, it adheres to rigorous defensive engineering rules:

### 1.1 Secret Masking & Redaction
- All regex-matched API keys (e.g., `shpat_`, `shpca_`, `sk_live_`, AWS keys, bearer tokens) and database passwords in `.env` or config files are automatically masked as `[REDACTED]` prior to persistence in database tables, log files, or AI prompts.
- Raw customer PII (emails, shipping addresses, phone numbers) captured during webhook inspection is scrubbed unless specifically configured in an encrypted testing environment.

### 1.2 Path Sandboxing & Directory Traversal Prevention
- All file reads and writes are strictly sandboxed within `base_path()` of the target project.
- Relative traversal patterns (`../`, `..\`) are resolved and rejected if the canonicalized path escapes the project root.

### 1.3 SSRF Defense in API Discovery
- Discovery endpoints (such as `/.well-known/customer-account-api`) must resolve only to public IP ranges and approved Shopify domain suffixes.
- Requests to private subnets (`127.0.0.1`, `10.0.0.0/8`, `192.168.0.0/16`, `169.254.169.254`) are blocked.

### 1.4 Non-Destructive Remediation
- Source code patches generated by Guardian are stored as `.patch` / unified diff proposals.
- No files are overwritten without an explicit interactive prompt or API confirmation with CSRF/Auth token verification.

### 1.5 Role-Based Dashboard Authorization
- The native Blade dashboard enforces Laravel authorization via the `viewGuardian` Gate and configured middleware (default: `['web', 'auth']`).
- Confidential partner notices and appeal logs are restricted to authorized administrators.
